# bbs-go 启动命令手册

> 适用版本：当前工作区 `master` @ `5bebf98`（2026-10-13）
> 适用环境：Windows PowerShell、Linux/macOS Shell、Docker Compose
> 目标：从零启动、日常开发、生产部署、升级回滚、故障排查

---

## 0. 最短路径

### 0.1 Docker（推荐，5 分钟）

```bash
# 1. 下载 MySQL 版 compose
curl -fsSL https://raw.githubusercontent.com/mlogclub/bbs-go/master/docker-compose.yml -o docker-compose.yml

# 2. 启动
docker compose up -d

# 3. 查看首次安装令牌
docker compose exec bbs-go cat /app/setup-token.txt
```

浏览器打开 `http://localhost:3000/install`，填入令牌与管理员账号完成安装。

> Windows PowerShell 中 `curl` 是 `Invoke-WebRequest` 的别名，不支持 `-fsSL`。请改用 `curl.exe -fsSL ...`，或使用 `Invoke-WebRequest -Uri <url> -OutFile docker-compose.yml`。

### 0.2 源码本地开发（Windows / Linux 通用）

```bash
# 终端 1：启动 Go API（8082）
go run -tags dev .

# 终端 2：启动前端开发服务器（3000）
cd web
corepack pnpm install --frozen-lockfile
pnpm dev
```

浏览器打开 `http://localhost:3000/install`；安装令牌在仓库根目录 `setup-token.txt`，或从终端 1 的日志中查找 `Generated one-time installation setup token`。

### 0.3 源码生产模式（单二进制 + SPA）

```bash
# 构建前端 SPA 并编入 Go 二进制
make build

# 启动（默认 8082）
./bbs-go
```

浏览器打开 `http://localhost:8082/install`。此模式不需要 Node 运行时。

## 1. 前置条件

| 依赖 | 版本要求 | 检查命令 | 说明 |
| --- | --- | --- | --- |
| Go | 1.26.0（`go.mod`） | `go version` | 必须 ≥ 1.26 |
| Node.js | 24.x（Dockerfile） | `node -v` | 仅前端构建/SSR 需要 |
| pnpm | 10.30.2（`packageManager`） | `pnpm -v` | 建议用 corepack 固定版本 |
| Docker | 24+，含 Compose v2 | `docker compose version` | 仅容器部署需要 |
| MySQL | 8.0+（compose 用 8.4） | — | 也可用 PostgreSQL 16 或 SQLite |
| PostgreSQL | 16（compose） | — | 可选 |
| make | GNU Make | `make -v` | Windows 建议 WSL/Git Bash |

固定 pnpm 版本：

```bash
corepack enable
corepack prepare pnpm@10.30.2 --activate
```

> 执行后如果 `pnpm -v` 仍显示 9.x，说明 `%APPDATA%\npm`（或全局 npm bin）在 PATH 中排在 corepack shim 之前。此时有两种做法：
> 1. 所有命令改用 `corepack pnpm <命令>`，强制使用 `packageManager` 声明的版本；
> 2. 或执行 `npm i -g pnpm@10.30.2` 覆盖全局 pnpm。
>
> 使用 pnpm 9 访问本项目的 `web/pnpm-workspace.yaml` 会报 `packages field missing or empty`。

首次拉取 Go 依赖：

```bash
go mod download
```

## 2. 本地开发环境

### 2.1 目录与端口

| 进程 | 端口 | 作用 |
| --- | --- | --- |
| Go API | 8082 | 接口、静态资源 `/res`、SPA 回退 |
| Vite / React Router Dev | 3000 | 页面开发服务器，代理 `/api`、`/res`、`/sitemap.xml` 到 8082 |

前端代理配置：`web/vite.config.ts:56-63`。
开发服务器要求 `web/.env` 中存在 `BBSGO_SERVER_URL`：

```env
BBSGO_SERVER_URL=http://localhost:8082
```

仓库当前已包含该文件；若缺失，请新建 `web/.env` 并写入上面一行。Vite 配置在启动和构建时都会读取它，缺失会直接抛错。

### 2.2 Windows PowerShell

打开两个终端，均在仓库根目录开始。

终端 1（后端）：

```powershell
cd d:\github_project\bbs-go
go run -tags dev .
```

终端 2（前端）：

```powershell
cd d:\github_project\bbs-go\web
corepack pnpm install --frozen-lockfile
pnpm dev
```

### 2.3 Linux / macOS

终端 1：

```bash
cd /path/to/bbs-go
go run -tags dev .
```

终端 2：

```bash
cd /path/to/bbs-go/web
corepack pnpm install --frozen-lockfile
pnpm dev
```

### 2.4 一条命令启动（仅 Linux/macOS/Git Bash）

```bash
make dev
```

该目标等价于：

```bash
go run -tags dev main.go &
cd web && pnpm dev
```

> Windows 原生 PowerShell 不支持 Makefile 中的 `&`、`trap` 等 shell 语法，请使用 2.2 的两个终端方式，或在 WSL/Git Bash 中执行。

### 2.5 首次安装

1. 打开 `http://localhost:3000/install`。
2. 填写站点名称、站点描述、BaseURL（本地可填 `http://localhost:3000`）。
3. 选择数据库：
   - SQLite：无需额外服务，数据库文件生成在配置文件同目录的 `bbs-go.db`；
   - MySQL / PostgreSQL：需先创建**空数据库**，安装器会校验库中不能已有表。
4. 填写管理员用户名、密码。
5. 填写安装令牌：
   - 本地源码运行：仓库根目录 `setup-token.txt`；
   - 或从后端日志复制：`Generated one-time installation setup token ... token=...`。
6. 提交后安装器会写入 `bbs-go.yaml`、建表、执行数据迁移、创建 owner 账号，并删除 `setup-token.txt`。

安装完成后：

```bash
curl http://localhost:8082/api/install/status
```

预期返回 `installed: true`。

### 2.6 管理员密码规则

安装管理员与普通用户使用同一套密码校验（`validate.IsPassword`）。密码过短或过弱会直接拒绝安装，避免安装入口成为弱口令后门。

### 2.7 本地 MySQL（Windows 服务）

检查服务状态与端口：

```powershell
Get-Service *mysql*
netstat -ano | findstr :3306
```

正常状态为 `Running`，启动类型 `Automatic`，3306 处于 `LISTENING`。

启动 / 停止 / 重启（需要管理员权限）：

```powershell
Start-Service MySQL80
Stop-Service MySQL80
Restart-Service MySQL80
```

> 服务名不一定是 `MySQL80`，先用 `Get-Service *mysql*` 确认。

MySQL 客户端默认不在 PATH，使用完整路径：

```powershell
& 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe' -u root -p
```

创建 bbs-go 所需的空库与专用账号：

```sql
CREATE DATABASE bbsgo DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'bbsgo'@'localhost' IDENTIFIED BY '请替换为强密码';
GRANT ALL PRIVILEGES ON bbsgo.* TO 'bbsgo'@'localhost';
FLUSH PRIVILEGES;
```

安装向导中填写对应的 DSN：

```
bbsgo:请替换为强密码@tcp(127.0.0.1:3306)/bbsgo?charset=utf8mb4&parseTime=True&multiStatements=true&loc=Local
```

注意：

- 安装器要求数据库为空（不能已有表），只建库、不要建表。
- `root` 免密登录被拒绝（`Access denied ... using password: NO`）是正常的安全配置，不代表服务没启动。
- 3306 已在监听但连接报 `Access denied`，说明服务正常、只是账号或密码不对。
- 启动日志位置：`C:\ProgramData\MySQL\MySQL Server 8.0\Data\<主机名>.err`，出现 `ready for connections` 即启动成功。

## 3. 本地生产模式（单二进制 SPA）

适合"一个进程 + 一个数据库"的小型部署，不需要 Node。

### 3.1 构建

```bash
# 构建 SPA 并编译 Go 二进制（输出 ./bbs-go）
make build
```

Windows 原生环境没有 make 时：

```powershell
cd d:\github_project\bbs-go\web
corepack pnpm install --frozen-lockfile

# pnpm build:spa 的脚本使用 POSIX 环境变量语法，Windows 原生 shell 不支持，
# 因此拆成三步执行：
$env:BBSGO_WEB_SPA = "true"
pnpm exec react-router build
node scripts/prepare-spa-build.mjs
Remove-Item Env:BBSGO_WEB_SPA

cd ..
go build -o bbs-go.exe .
```

> 在 Git Bash / WSL 中可以直接执行 `pnpm build:spa`。

> `web/embed.go` 使用 `//go:embed all:build/spa`。如果 `web/build/spa/index.html` 不存在，直接 `go build` 会报：
> `pattern all:build/spa: no matching files found`。
> 解决方式：先执行 `pnpm build:spa`，或开发时使用 `go run -tags dev .`。

### 3.2 启动

Linux/macOS：

```bash
BBSGO_ENV=prod ./bbs-go
```

Windows PowerShell：

```powershell
$env:BBSGO_ENV = "prod"
.\bbs-go.exe
```

默认监听 `8082`，访问 `http://localhost:8082`。

### 3.3 后台运行

使用 systemd（Linux）：

```ini
# /etc/systemd/system/bbs-go.service
[Unit]
Description=bbs-go
After=network.target mysql.service

[Service]
Type=simple
WorkingDirectory=/opt/bbs-go
ExecStart=/opt/bbs-go/bbs-go
Environment=BBSGO_ENV=prod
Restart=always
RestartSec=5
User=bbsgo

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now bbs-go
sudo systemctl status bbs-go
sudo journalctl -u bbs-go -f
```

> `User=bbsgo`、`WorkingDirectory`、`After=` 需按实际环境调整；使用 PostgreSQL 时把 `After=mysql.service` 改为 `After=postgresql.service`，并确保运行用户对 `res/uploads`、`logs`、`data` 有写权限。

使用 PM2（仓库自带 `ecosystem.config.cjs`，仅启动 Go 进程）：

```bash
pm2 start ecosystem.config.cjs
pm2 logs bbs-go
pm2 restart bbs-go
pm2 stop bbs-go
```

> `ecosystem.config.cjs` 只管理 Go 后端。若使用 SSR 模式，需要额外用 PM2 或 systemd 管理 `node scripts/serve-ssr.mjs`。

### 3.4 目录约定

| 路径 | 用途 | 是否需持久化 |
| --- | --- | --- |
| `bbs-go.yaml` | 运行配置（含数据库连接） | 是 |
| `logs/bbs-go.log` | 应用日志（可配置） | 建议 |
| `res/uploads/` | 本地上传的图片与附件 | 是 |
| `data/topic_index/` | Bleve 搜索索引 | 可重建 |
| `bbs-go.db` | SQLite 数据库（仅 SQLite） | 是 |

配置文件查找顺序：当前工作目录的 `bbs-go.yaml` → 可执行文件同目录的 `bbs-go.yaml`。启动前先 `cd` 到配置所在目录，或把配置放在二进制旁边。

## 4. SSR 模式（源码运行）

默认前端产物是 SSR，需要 Node 进程与 Go 进程同时运行。

### 4.1 构建

```bash
cd web
corepack pnpm install --frozen-lockfile
pnpm build:ssr
```

产物：

- `web/build/client/`：浏览器静态资源
- `web/build/server/index.js`：SSR 服务入口

### 4.2 启动

终端 1（Go API）：

```bash
cd /path/to/bbs-go
BBSGO_ENV=prod ./bbs-go
```

终端 2（Node SSR）：

```bash
cd /path/to/bbs-go/web
BBSGO_SERVER_URL=http://127.0.0.1:8082 PORT=3000 pnpm start
```

Windows PowerShell：

```powershell
cd d:\github_project\bbs-go\web
$env:BBSGO_SERVER_URL = "http://127.0.0.1:8082"
$env:PORT = "3000"
pnpm start
```

访问 `http://localhost:3000`。

### 4.3 说明

- SSR 服务会把 `/api/*`、`/res/*`、`/sitemap.xml` 反向代理到 Go（`web/scripts/serve-ssr.mjs:64-104`）。
- 若 Go 未启动，SSR 页面会返回 502。
- `BBSGO_SERVER_URL` 必须是 Node 进程可访问的地址；Docker 中为 `http://127.0.0.1:8082`。
- 修改前端后必须重新 `pnpm build:ssr` 并重启 Node；Go 无需重启。

## 5. Docker 部署

### 5.1 方式一：官方镜像（MySQL）

```bash
curl -fsSL https://raw.githubusercontent.com/mlogclub/bbs-go/master/docker-compose.yml -o docker-compose.yml
docker compose up -d
```

访问 `http://localhost:3000`。

查看首次安装令牌：

```bash
docker compose exec bbs-go cat /app/setup-token.txt
```

> 令牌写在 bbs-go 进程的工作目录（官方镜像 `WORKDIR=/app`），不是 `/app/data` 数据卷。
> 若自定义了工作目录或配置路径，令牌位于 `bbs-go.yaml` 同目录；安装成功后会立即删除，文件不存在时从日志中查找。

或从日志提取：

```bash
docker compose logs bbs-go | grep "setup token"
```

PowerShell：

```powershell
docker compose logs bbs-go | Select-String "setup token"
```

### 5.2 方式二：官方镜像（PostgreSQL）

```bash
curl -fsSL https://raw.githubusercontent.com/mlogclub/bbs-go/master/docker-compose.postgresql.yml -o docker-compose.yml
docker compose up -d
docker compose exec bbs-go cat /app/setup-token.txt
```

### 5.3 方式三：本地源码构建镜像

```bash
# 构建镜像（与 compose 中的 image 名称保持一致）
docker build -t mlogclub/bbs-go:latest .

# 启动
docker compose up -d

# 查看状态
docker compose ps
docker compose logs -f bbs-go
```

> compose 中 `build:` 段默认被注释，使用 `image:` 拉取。若要 compose 直接构建，取消注释 `build:` 并执行 `docker compose up -d --build`。

### 5.4 使用 own GHCR 镜像

当前仓库 CI 会把镜像推到：

```
ghcr.io/ldsun2024/bbs-go:latest
ghcr.io/ldsun2024/bbs-go:sha-<commit>
```

仓库自带 compose 的 image 是 `mlogclub/bbs-go:${BBSGO_IMAGE_TAG:-latest}`。要改用 GHCR，新增 `docker-compose.override.yml`：

```yaml
services:
  bbs-go:
    image: ghcr.io/ldsun2024/bbs-go:latest
```

然后：

```bash
docker compose pull
docker compose up -d
```

登录 GHCR（私有镜像时需要）：

```bash
echo $GITHUB_TOKEN | docker login ghcr.io -u <github-username> --password-stdin
```

### 5.5 Docker 中的数据库行为

compose 会注入以下环境变量（`docker-compose.yml:47-52`）：

| 变量 | 作用 |
| --- | --- |
| `BBSGO_INSTALL_DOCKER_BUILTIN_MYSQL=true` | 使用内置 MySQL，安装向导不再要求填写连接信息 |
| `BBSGO_DOCKER_BUILTIN_MYSQL_HOST` | 数据库主机（`mysql`） |
| `BBSGO_DOCKER_BUILTIN_MYSQL_PORT` | 端口（`3306`） |
| `BBSGO_DOCKER_BUILTIN_MYSQL_DATABASE` | 库名（默认 `bbsgo`） |
| `BBSGO_DOCKER_BUILTIN_MYSQL_USERNAME` | 用户名（默认 `bbsgo`） |
| `BBSGO_DOCKER_BUILTIN_MYSQL_PASSWORD` | 密码（默认 `bbsgo_password`） |

PostgreSQL 版本对应 `BBSGO_INSTALL_DOCKER_BUILTIN_POSTGRESQL*`。

> 默认口令仅用于本地演示。对外部署必须在 `.env` 或 compose 中覆盖 `BBSGO_DOCKER_MYSQL_PASSWORD`、`BBSGO_DOCKER_MYSQL_ROOT_PASSWORD`、`BBSGO_DOCKER_POSTGRESQL_PASSWORD`。

### 5.6 常用 Docker 命令

```bash
# 状态与日志
docker compose ps
docker compose logs -f --tail=200 bbs-go

# 重启 / 停止 / 启动
docker compose restart bbs-go
docker compose stop
docker compose start

# 进入容器
docker compose exec bbs-go sh
docker compose exec mysql mysql -ubbsgo -pbbsgo_password bbsgo

# 健康检查
curl -f http://localhost:3000/api/install/status

# 拉取新镜像并重建
docker compose pull
docker compose up -d

# 停止并删除容器（保留数据卷）
docker compose down

# 停止并删除容器与数据卷（危险：数据库清空）
docker compose down -v
```

### 5.7 远程部署脚本

仓库提供 `deploy/remote-deploy.sh`，流程：拉镜像 → 校验 compose → 重建 → 健康检查（最多 90 秒）。

```bash
# 服务器上执行
bash /opt/bbs-go/repo/deploy/remote-deploy.sh
```

注意事项：

1. 脚本中的镜像地址写死为 `ghcr.io/aishangwuji/bbs-go:latest`（`remote-deploy.sh:19`）。当前仓库归属为 `ldsun2024`，使用前需改成：
   ```bash
   IMAGE=ghcr.io/ldsun2024/bbs-go:latest
   ```
2. 健康检查使用容器名 `bbs-go`（`docker inspect bbs-go`）。compose 默认容器名是 `<项目名>-<服务名>-1`（例如 `bbs-go-bbs-go-1`）。两种解决方式：
   - 在 compose 的 `bbs-go` 服务下增加 `container_name: bbs-go`；
   - 或修改脚本中的容器名。
3. 部署目录可用 `BBSGO_DEPLOY_DIR` 覆盖，默认 `/opt/bbs-go`。

## 6. 编译与打包

### 6.1 Make 目标

| 命令 | 作用 |
| --- | --- |
| `make build` | 构建 SPA + 编译 Go 二进制（`./bbs-go`） |
| `make build-go` | 只编译 Go；SPA 缺失时自动构建 |
| `make build-linux` | 构建 linux/amd64 二进制（含 SPA） |
| `make package` | 构建全部支持平台并打 tar.gz |
| `make package GOOS=linux GOARCH=amd64` | 构建单个平台包 |
| `make run` | 构建 SPA 后 `go run main.go` |
| `make run-go` | `go run main.go`，SPA 缺失时自动构建 |
| `make dev` | Go（`-tags dev`）+ Vite 开发服务器 |
| `make test` | `go test ./...`（会先确保 SPA 存在） |
| `make check` | Go 测试 + 前端 typecheck + lint |
| `make clean` | 删除二进制与 dist |
| `make clean-web` | 删除前端构建产物 |
| `make web-install` | `corepack pnpm install --frozen-lockfile` |
| `make web-dev` | 启动 Vite 开发服务器 |
| `make web-build-spa` | 构建 SPA |
| `make web-build-ssr` | 构建 SSR |
| `make web-typecheck` | 前端类型检查 |
| `make web-lint` | 前端 ESLint |
| `make generator` | 代码生成（codegen） |
| `make generate-permissions` | 生成前端权限常量 |

> Makefile 大量使用 POSIX shell 语法（`cp`、`rm`、`&`、`trap`、`tar`）。Windows 原生 PowerShell 下不可直接执行，请使用 WSL / Git Bash，或按 3.1、6.2 节的手动命令操作。

### 6.2 手动交叉编译

```bash
# Linux amd64（先确保 web/build/spa 已存在）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o bbs-go-linux-amd64 .
```

Windows PowerShell：

```powershell
$env:CGO_ENABLED = "0"
$env:GOOS = "linux"
$env:GOARCH = "amd64"
go build -trimpath -ldflags="-s -w" -o bbs-go-linux-amd64 .
```

支持的目标平台见 `Makefile:10`：linux/amd64、linux/arm64、windows/amd64、windows/arm64、darwin/amd64、darwin/arm64、freebsd/amd64、freebsd/arm64。

### 6.3 构建产物说明

| 产物 | 位置 | 说明 |
| --- | --- | --- |
| Go 二进制 | 根目录 `bbs-go` / `bbs-go.exe` | SPA 已嵌入 |
| SPA | `web/build/spa/` | 供 Go embed |
| SSR client | `web/build/client/` | 浏览器资源 |
| SSR server | `web/build/server/index.js` | Node SSR 入口 |
| 发布包 | `dist/*.tar.gz` | 含二进制、locales、res/images |

## 8. 配置与环境变量

### 8.1 配置文件

从示例复制：

```bash
cp bbs-go.example.yaml bbs-go.yaml
```

Windows：

```powershell
Copy-Item bbs-go.example.yaml bbs-go.yaml
```

常用字段：

```yaml
port: 8082
allowedOrigins:
  - "https://your-domain.com"
installed: false

ipLocator:
  ipv4DataPath: /path/to/ip2region_v4.xdb
  ipv6DataPath: /path/to/ip2region_v6.xdb

logger:
  filename: ./logs/bbs-go.log
  maxSize: 100
  maxAge: 10
  maxBackups: 10

db:
  type: mysql              # mysql | postgresql | sqlite
  url: user:pass@tcp(127.0.0.1:3306)/bbsgo?charset=utf8mb4&parseTime=True&multiStatements=true&loc=Local
  maxIdleConns: 50
  maxOpenConns: 200
  logLevel: warn

search:
  indexPath: ./data/topic_index
```

说明：

- `installed` 由安装器写入，不要手工改为 `true`，否则会跳过安装但数据库为空。
- PostgreSQL 的 `db.url` 由安装向导生成（形如 `postgres://user:pass@host:5432/db?sslmode=disable`），不要照抄上面的 MySQL DSN。
- `idCodec.key` 由安装器随机生成；丢失会导致旧链接中的编码 ID 无法解析。
- `db.type=sqlite` 时，数据库文件固定为配置目录下的 `bbs-go.db`，连接数被强制为 1。
- `search.indexPath` 为空时，安装器会写入配置目录下的 `data/topic_index`。

### 8.2 环境变量

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `BBSGO_ENV` | `dev` | `prod` 时启动定时任务、上传 key 不加 `test/` 前缀 |
| `BBSGO_SERVER_URL` | 无 | SSR/Vite 代理目标，缺失会直接报错 |
| `PORT` | `3000` | Node SSR 监听端口 |
| `BBSGO_WEB_SPA` | 无 | 构建时设为 `true` 输出 SPA |
| `BBSGO_IMAGE_TAG` | `latest` | compose 镜像 tag，可用于回滚 |
| `BBSGO_DEPLOY_DIR` | `/opt/bbs-go` | 远程部署脚本的 compose 目录 |
| `BBSGO_DOCKER_MYSQL_*` | 见 compose | Docker 内置 MySQL 连接信息 |
| `BBSGO_DOCKER_POSTGRESQL_*` | 见 compose | Docker 内置 PostgreSQL 连接信息 |
| `TZ` | `Asia/Shanghai`（Docker） | 时区，影响任务周期与展示 |

设置示例：

Linux/macOS：

```bash
export BBSGO_ENV=prod
export BBSGO_SERVER_URL=http://127.0.0.1:8082
```

Windows PowerShell：

```powershell
$env:BBSGO_ENV = "prod"
$env:BBSGO_SERVER_URL = "http://127.0.0.1:8082"
```

## 9. 升级、回滚与备份

### 9.1 Docker 升级

```bash
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=100 bbs-go
```

> 若镜像是本地源码构建的（`docker build -t mlogclub/bbs-go:latest .`），升级时应先 `git pull`，再执行 `docker compose build && docker compose up -d`，不要直接 `pull`，否则会用远端同名镜像覆盖本地构建。

### 9.2 Docker 回滚

若 compose 的 image 使用 `${BBSGO_IMAGE_TAG}`（仓库自带 compose 是这种写法）：

```bash
BBSGO_IMAGE_TAG=sha-<commit> docker compose up -d --no-deps
```

Windows PowerShell：

```powershell
$env:BBSGO_IMAGE_TAG = "sha-<commit>"
docker compose up -d --no-deps
```

若使用固定 `:latest`，先拉取旧 tag 并重新打标签：

```bash
docker pull ghcr.io/ldsun2024/bbs-go:sha-<commit>
docker tag ghcr.io/ldsun2024/bbs-go:sha-<commit> ghcr.io/ldsun2024/bbs-go:latest
docker compose up -d --no-deps
```

> 仅 `docker pull sha-xxx` 不会改变 compose 实际使用的镜像，必须通过 tag 覆盖或 `docker tag`。

### 9.3 源码部署升级

```bash
git pull
make build
sudo systemctl restart bbs-go
```

前端变更需要重新 `make build`（SPA 嵌入二进制）；SSR 模式需要额外 `pnpm build:ssr` 并重启 Node。

### 9.4 备份

MySQL：

```bash
docker compose exec -T mysql mysqldump -ubbsgo -pbbsgo_password bbsgo > backup-$(date +%F).sql
```

PostgreSQL：

```bash
docker compose exec -T postgresql pg_dump -U bbsgo bbsgo > backup-$(date +%F).sql
```

同时备份持久化目录：

```bash
tar -czf bbs-go-data-$(date +%F).tar.gz docker-data/data docker-data/uploads
```

PostgreSQL 版本目录为 `docker-data-postgresql/`。

> 若 compose 文件不是默认的 `docker-compose.yml`，在 `docker compose` 后加 `-f <文件名>`，例如 `docker compose -f docker-compose.postgresql.yml exec ...`。

### 9.5 恢复

MySQL：

```bash
docker compose exec -T mysql mysql -ubbsgo -pbbsgo_password bbsgo < backup-2026-10-20.sql
```

PostgreSQL：

```bash
docker compose exec -T postgresql psql -U bbsgo bbsgo < backup-2026-10-20.sql
```

恢复上传目录：

```bash
tar -xzf bbs-go-data-2026-10-20.tar.gz
```

## 10. 故障排查

### 10.1 编译/启动错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `pattern all:build/spa: no matching files found` | 未构建前端 SPA | `make web-build-spa`；开发用 `go run -tags dev .` |
| `BBSGO_SERVER_URL is required` | 缺少 `web/.env` 或环境变量 | 写入 `web/.env` 或 `export BBSGO_SERVER_URL=...` |
| `config file not found` | 没有 `bbs-go.yaml` | 正常：未安装状态会使用默认配置，访问 `/install` |
| `invalid or missing setup token` | 令牌错误/文件已删除 | 读取 `setup-token.txt` 或日志；已安装后令牌会被删除 |
| `BBSGO_WEB_SPA=true is not recognized` | Windows 原生 shell 不识别 POSIX 环境变量语法 | 用 3.1 节 PowerShell 三步构建，或改用 Git Bash/WSL |
| `please use an empty database for installation` | 目标库已有表 | 换空库，或确认连接的是正确数据库 |
| `database connection timeout` | 地址/端口/防火墙错误 | 检查 host、port、安全组；Docker 内不要用 `localhost` 连 MySQL |
| `failed to parse int from ?`（cron） | 定时表达式不合法 | 当前 `0 4 ? * *` 受支持；自定义时使用标准 5 段表达式 |

### 10.2 端口占用

Windows：

```powershell
netstat -ano | findstr :8082
netstat -ano | findstr :3000
taskkill /PID <pid> /F
```

Linux/macOS：

```bash
lsof -i :8082
lsof -i :3000
kill -9 <pid>
```

修改端口：

- Go：`bbs-go.yaml` 中 `port`；
- SSR：`PORT` 环境变量；
- Vite：`web/vite.config.ts` 中 `server.port`。

### 10.3 页面能打开但接口 502/404

1. 确认 Go 进程存活：`curl http://127.0.0.1:8082/api/install/status`。
2. 确认 SSR 的 `BBSGO_SERVER_URL` 指向 Go。
3. 确认 Nginx/网关没有把 `/api` 路由到错误上游。
4. 查看 Node SSR 日志与 Go 日志。

### 10.4 安装后仍跳转 `/install`

- 检查 `bbs-go.yaml` 中 `installed: true`；
- 检查 `/api/install/status` 返回；
- 清理浏览器缓存后重试；
- 若手工改过 `installed`，数据库可能未建表，需恢复为 `false` 重新安装。

### 10.5 上传失败

- 检查 `res/uploads` 目录权限（容器内为 `/app/res/uploads`）；
- 检查反向代理 `client_max_body_size`，默认 Nginx 1 MB 会拦截图片；
- 附件还受系统配置中的大小与扩展名白名单限制；
- 本地图片上传上限当前存在常量问题（实际约 10 GiB），但不应依赖该值做容量规划。

### 10.6 SQLite 锁等待/写入失败

SQLite 模式强制单连接（`internal/install/install.go:377-380`）。不要同时运行多个实例，也不要在 SQLite 模式下做高频并发写入。

### 10.7 Docker 健康检查失败

```bash
docker compose ps
docker compose logs --tail=200 bbs-go
docker inspect --format '{{.State.Health.Status}}' <container>
```

常见原因：

- Go 进程启动失败（配置/数据库）；
- Node SSR 启动失败（缺少 `build/server`、`BBSGO_SERVER_URL`）；
- `entrypoint.sh` 在任一子进程退出时会整体退出，因此要同时看两段日志。

### 10.8 前端依赖/版本问题

典型报错：

```
ERROR  packages field missing or empty
```

原因：`web/pnpm-workspace.yaml` 只包含 `onlyBuiltDependencies` 等构建白名单，没有 `packages` 字段。pnpm 9 强制要求工作区文件声明 `packages`；项目 `package.json` 的 `packageManager` 声明使用 pnpm 10.30.2，pnpm 10 允许省略该字段。

处理（推荐，不改仓库文件）：

```bash
cd web
corepack pnpm -v                  # 应输出 10.30.2
corepack pnpm install --frozen-lockfile
```

如果 corepack 不可用，或 `pnpm -v` 仍为 9.x：

```bash
npm i -g pnpm@10.30.2
pnpm -v
```

清理后重装：

```bash
cd web
rm -rf node_modules
corepack pnpm install --frozen-lockfile
```

Windows 删除目录：

```powershell
Remove-Item -Recurse -Force web\node_modules
```

> 不建议仅为绕过报错而在 `pnpm-workspace.yaml` 添加 `packages: ['.']`。这会让 pnpm 9 继续安装，但锁文件与构建白名单按 pnpm 10 维护，后续容易出现依赖树或 postinstall 行为不一致。

### 10.9 能不能改用 npm

项目是 pnpm 管理的（`pnpm-lock.yaml`、`pnpm-workspace.yaml`、`.npmrc` 中的 `only-built-dependencies`、`packageManager` 均指向 pnpm），**不建议用 `npm install`**：它会忽略 pnpm 锁文件、生成 `package-lock.json`，并产生另一套依赖树。

在依赖已经用 pnpm 安装好的前提下，npm 可以执行不依赖 pnpm 的脚本：

| 命令 | 是否可用 | 说明 |
| --- | --- | --- |
| `npm run dev` | 可用 | 直接调用 `react-router dev` |
| `npm run build:ssr` | 可用 | 直接调用 `react-router build` |
| `npm start` | 可用 | 需先有 `build/server` |
| `npm run typecheck` / `npm run lint` | 可用 | 直接调用 tsc / eslint |
| `npm run build` | 受 pnpm 版本影响 | 脚本内容是 `pnpm build:ssr`，pnpm 9 会报 workspace 错误 |
| `npm run build:spa` | Windows 不可用 | 脚本使用 POSIX 的 `BBSGO_WEB_SPA=true` 语法 |
| `npm install` | 不建议 | 忽略 pnpm 锁文件，`.npmrc` 的 pnpm 配置会被 npm 告警 |

因此：

- 只是启动开发服务器：`npm run dev` 可以，但更推荐统一用 `corepack pnpm dev`。
- 需要构建：优先 `corepack pnpm build:ssr` / `corepack pnpm build:spa`，或在 Windows 上用 `corepack pnpm exec react-router build` 加环境变量分步执行。
- 不要把 `npm install` 作为标准安装方式写进团队流程。
