# B5 · 通知与未读

> 所属：细节打磨 ｜ 工作量 S（约 2 小时）｜ 依赖：无
> 原型：`prototype.html`

## 1. 问题

通知系统有数据（`t_message` + 未读计数），但视觉上没有传达"该处理什么"：

| # | 问题 | 影响 |
|---|---|---|
| 1 | 未读只是数字角标 | 一堆数字堆在导航上，无法分辨哪条更重要 |
| 2 | 消息中心没有类型导航 | 回复、赞、关注、系统通知混在一条流里 |
| 3 | 已读与未读仅靠字重区分 | 扫视时很难找出未读项 |
| 4 | 没有时间分组 | 100 条消息平铺，"今天发生了什么"看不出来 |
| 5 | 空态直接显示空白 | 用户以为加载失败 |

## 2. 目标

- 扫一眼就能找到未读的那几条
- 能按类型快速过滤
- 时间上有分段，形成"最近 / 更早"的节奏

## 3. 方案

### 3.1 结构

```
┌ 顶栏 ─────────────────────────────────┐
│ ...  🔔⑤  ← 角标：8px 红点 + 数字      │
└───────────────────────────────────────┘
┌ 左导航 180 ┬ 消息列表 ────────────────┐
│ 全部  12   │ 今天                       │
│ 回复   8   │ ▍小满 回复了你的话题       │ ← 未读：3px 墨绿条 + 浅底
│ 赞     3   │ ▍周舟 赞了你的回答         │
│ 关注   1   │ 系统 你的邮箱已验证         │ ← 已读：无条、常规底色
│ 系统       │ 昨天                       │
│            │ 林一 关注了你               │
└────────────┴───────────────────────────┘
```

### 3.2 规格

| 元素 | 规格 |
|---|---|
| 顶栏角标 | 8px 红点 + 10.5px 白字，`radius 999`，最大显示 `99+` |
| 左导航 | 宽 180，项高 36，未读数右对齐 11.5px `--muted` |
| 时间分组标题 | 11.5px，`--muted`，上方 20 下 8 |
| 消息项 | 高 72，内边距 `16px 20px`，头像 32 |
| 未读标记 | 左 3px `--brand` 条（距上下 14），背景 `--brand-soft` 30% |
| 未读标题 | 字重 600，`--text` |
| 已读标题 | 字重 400，`--text-2` |
| 类型图标 | 16px lucide，放在头像右下角小圆内 |

### 3.3 交互

- 点击消息项 → 标记已读 + 跳转目标
- 「全部标为已读」放在列表右上角，文字按钮
- 左导航切换不刷新页面（客户端过滤）
- 未读数归零后，顶栏角标消失而不是显示 0

## 4. 验收

- [ ] 一屏内能立刻分辨哪些是未读
- [ ] 切换类型后列表立即过滤，未读数同步
- [ ] 时间分组标题不参与 hover
- [ ] 角标超过 99 显示 99+
- [ ] 空态使用 B3 的统一空态组件
