# bbs-go 设计优化集

> 建立：2026-10-20
> 上游基线：`docs/UI设计规范.md` v2.0（暖纸编辑风 + 墨绿主色 + 衬线标题 + 细颗粒）
> 范围：15 个设计项，每项一份设计文档 + 一个可打开的原型页
> 约束：**只改样式与组件外观，不改业务逻辑、不改数据结构、不改既有接口契约**

---

## 怎么用

1. 打开 `assets/design.css` 所在目录，直接双击任意 `prototype.html`
2. 每份 `design.md` 的结构固定：问题（带代码证据）→ 目标 → 方案 → 规格 → 实现 → 验收
3. 建议先看 `a1`（正文）、`a2`（主页）、`a5`（类型区分），这三项改动最直观

## 实施建议（按风险与收益排序）

### 第 1 批 · 阅读体验（8h）

```
A1 正文排版  →  A5 内容类型区分  →  A2 个人主页
```

理由：这三项覆盖"看内容"和"看人"两条主路径，改完气质变化最明显，且都是纯 CSS。

### 第 2 批 · 必经路径（10h）

```
A3 登录  →  A4 发布  →  B3 空态
```

理由：登录与发布是每个用户都会走的第一步，空态覆盖所有"没有数据"的场景。

### 第 3 批 · 结构与适配（12h）

```
B1 移动端  →  B2 后台  →  B5 通知
```

理由：涉及组件结构调整，需要逐页验收；移动端依赖 A5 的 `data-type` 注入。

### 第 4 批 · 补充能力（9h）

```
C5 骨架  →  C4 图表  →  C3 打印  →  B4 图标徽章
```

理由：都是标准化工作，可以批量推进。

### 第 5 批 · 需后端协作（4h+）

```
C1 OG 图  →  C2 邮件模板
```

理由：这两项要动后端代码，建议在前端视觉全部稳定后再做，避免同时改两端。

## 与既有规范的关系

| 文档 | 定位 |
|---|---|
| `docs/UI设计规范.md` v2.0 | **设计基线**：token、布局体系、组件规格、落地步骤 |
| `docs/design/*`（本目录） | **落地细化**：逐项问题的具体方案与原型 |
| `docs/prototype/ui-*.html` | **整页效果**：列表页、详情页、对比页、质感对比 |

三者的 token 完全一致：暖白 `#FAF7F2`、墨绿 `#14665A`、赤陶 `#C4552B`、圆角 6、衬线标题、细颗粒底纹。

## 参数基线（v2.1 已统一）

所有 15 项共用一套参数，**不允许在原型里另写数值**。

| 维度 | 唯一允许值 |
|---|---|
| 字号 | **9 档**：31 / 25 / 20 / 16 / 15 / 14 / 13 / 12 / 11 |
| 圆角 | **4 档**：4 / 6 / 8 / 999 |
| 按钮高度 | **3 档**：40（lg）/ 34（默认）/ 26（sm） |
| 输入框高度 | **38** |
| 表格行高 | 44，表头 38 |
| 间距 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 64 |
| 颜色 | 只用 `UI设计规范.md` 4.1 的 token，不写死新值 |
| 阴影 | 卡片无，仅浮层 |
| 字体 | 标题衬线、正文黑体、数字等宽 |
| 动效 | 只做淡入与变色，不做位移与缩放 |

### 介质例外（4.10）

OG 图、邮件、打印、原型展示容器可以偏离上表，但同一介质内部必须自洽：

| 介质 | 允许 |
|---|---|
| OG 分享卡 | 字号 52/28/24/22，圆角 10/12 |
| 邮件模板 | 字号 21/14/11.5，600 宽，table 布局 |
| 打印 | `pt` 单位，11.5pt / 15pt / 10pt |
| 原型容器 | 手机框 34px 圆角 |

判断标准：用户看到的是"图片 / 邮件 / 纸"时才套例外；产品页面一律回到上表。
