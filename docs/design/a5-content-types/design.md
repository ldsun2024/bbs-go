# A5 · 内容类型区分度

> 所属：内容呈现 ｜ 工作量 S（约 2 小时）｜ 依赖：无
> 原型：`prototype.html`

## 1. 问题

系统里有四种内容形态，但在列表里的视觉几乎一样：

| 类型 | 表 | 现有区分方式 |
|---|---|---|
| 话题 | `t_topic`（type=0） | 一个灰色分类标签 |
| 动态 | `t_topic`（type=1） | 同上 |
| 问答 | `t_topic`（type=2） | 同上，可能有「已解决」标签 |
| 文章 | `t_article` | 独立列表页，但列表项样式与话题一致 |

后果：

- 首页混排时，用户要读标题和标签才能判断"这是提问还是分享"
- 问答的「悬赏 / 已解决」淹没在标签堆里
- 文章与话题在不同页面却是同一张脸，切换页面时缺少"场景转换"感

## 2. 目标

- 扫视 0.5 秒内能分辨类型，不需要读文字
- 不只依赖颜色（色弱用户同样可辨）
- 不引入新组件，只在现有列表项上叠两个元素

## 3. 方案

### 3.1 两个信号叠加

1. **左侧 3px 类型色条** —— 整列扫视时的第一层信号
2. **标题前的类型徽标**（19px 高，文字 + 底色）—— 精确信号，不依赖颜色

### 3.2 色板

| 类型 | 色条 / 徽标底色 | 徽标文字 | 说明 |
|---|---|---|---|
| 话题 | `--brand` `#14665A` | 话题 | 主色，因为它是内容主干 |
| 动态 | `--slate` `#4A6274` | 动态 | 冷灰蓝，比话题轻 |
| 问答 | `--warm` `#C4552B` | 问答 | 赤陶，与"悬赏/待解决"同一语义色 |
| 文章 | `--indigo` `#3B4A6B` | 文章 | 深靛，长文更"正式" |

四种颜色在明暗两套主题下都保持可辨；同时徽标始终带文字，色弱用户不受影响。

### 3.3 规格

| 元素 | 规格 |
|---|---|
| 色条 | 宽 3，`top/bottom: 16px`，`border-radius: 0 3px 3px 0`，贴左边缘 |
| 徽标 | 高 20，内边距 0 6，`radius 4`，字号 11，字重 600 |
| 位置 | 徽标在标题前，与标题同基线，右侧留 8px |
| 列表项左内边距 | 由 20 增至 24，给色条留出呼吸 |

### 3.4 实现

```css
.topic-item { position: relative; padding-left: 24px; }
.topic-item::before {
  content: "";
  position: absolute;
  left: 0;
  top: 16px;
  bottom: 16px;
  width: 3px;
  border-radius: 0 3px 3px 0;
  background: var(--brand);
}
.topic-item[data-type="tweet"]::before { background: var(--slate); }
.topic-item[data-type="qa"]::before   { background: var(--warm); }
.topic-item[data-type="article"]::before { background: var(--indigo); }
```

`data-type` 由列表项渲染时按 `topic.type` / 内容来源注入，**不需要改后端**。

## 4. 验收

- [ ] 四种类型混排时，不看文字也能区分
- [ ] 灰色截图（去色）后，仍能靠徽标文字区分
- [ ] 色条不与置顶标记、悬赏标签打架
- [ ] 暗色模式下四种颜色亮度接近，不出现某一种特别刺眼
