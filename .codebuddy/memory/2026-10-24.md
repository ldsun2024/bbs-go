- 素材：`111节-黄金课-实战总结.xlsx`（269 行，编号/学号/主题/操作总结/备注）、`96-黄金课-个人分析总结.xlsx`（199 行同构，大量合并单元格，需 ffill）、`【胡数】技术部共享文档.xlsx`（`需求池` sheet 41 行，一级/二级需求、需求详情、功能说明）。
- 结果：`bbsgo_ren` 话题 96 条（1 欢迎帖 + 70 普通 + 25 问答）、文章 15 篇、标签 8 个、topic_tag 34 条；新建分类 `黄金课复盘`(normal,id=14)、`实战答疑`(qa,id=15)、`技术需求`(normal,id=16)。
- 随机化：作者 1/2 随机，create_time 落在过去 120~150 天，view 60~3200，like 按 view 的 2%~9%，8% 推荐、4% 置顶；`t_user.topic_count` 已按实际重算。
- **标题去重是关键**：第一版 95 条只有 46 个不同标题（Excel 主题列大量重复），改为「素材按正文前 120 字去重 + 候选标题集合去重」后达到 95/95、15/15 全唯一。
- 问答标题单独重做两次：最终用正文首句截 28 字 + `…，该怎么办？`，长度 ≤35 字。
- **坑 1（pymysql）**：`cursor.execute(sql, args)` 内部是 `query % escaped_args`，正文含 `%` 会报 `TypeError: not enough arguments for format string`。必须把文本参数里的 `%` 换成 `%%`。
- **坑 2**：`t_topic` 的 INSERT 列 28 个，VALUES 多写了一个末尾 `''` 导致值数 29，同样报 format string 错误。教训：长 INSERT 要核对「列数 = 占位符数 = 参数个数」。
- **坑 3（PowerShell 验证）**：`Invoke-WebRequest` 默认按 Latin-1 解码 UTF-8 中文，`-match "三孚"` 恒为 false，会误判页面没数据。要用 `[System.Text.Encoding]::UTF8.GetString($r.RawContentStream.ToArray())`。
- 插入前备份：`logs/before-seed-20261024.sql`（mysqldump 了 t_topic/t_article/t_category/t_tag/t_topic_tag/t_user）。

## 当前页面布局诊断（用户提出「功能够用但页面看着不对」）

- 用 Playwright（Chrome，1440 / 390 两档）实截：`docs/screens/current-topics-fold.png`（桌面列表）、`docs/screens/current-topic-detail.png`（详情）、`docs/screens/current-topics-390.png`（移动端）。**注意详情路由是 `/topic/{id}`（单数）**，`/topics/{id}` 是 404。
- 硬伤（有截图依据）：
  1. 移动端顶栏 logo 被压成扁长条（`h-8` 固定高、宽自适应，原图比例不对）。
  2. 所有分类图标都是同一个红色小方块（占位感），而「全部」是蓝色网格图标，语义与颜色都冲突。
  3. 置顶标签用橙色胶囊，与紫色主色（`--primary` 靛紫）冲突。
  4. 桌面三栏比例失衡：左 180 / 中约 530 / 右 240，主内容过窄，中文标题频繁换行；容器 1280 但主区被两栏挤压。
  5. 右栏三种风格混杂：未登录卡（淡紫渐变）+ 每日签到（紫色大按钮）+ 排行卡（白卡无标题分隔）。
  6. 详情页左侧浮动操作条（点赞/评论/收藏）是圆形图标，浮在内容区外贴边；评论区输入框是淡蓝紫底，与整体不搭；空态是巨大的灰色线稿。
  7. 全站背景 `linear-gradient(136deg,#edf0ff99,#e7f6fa99)` 淡紫渐变 + 10px 圆角 + 轻阴影 = 模板感主因。
  8. 字号层级弱：正文 14、标题 15/26，仅靠字号差，无字重/字体族层次；间距几乎只有 10px 一档。
